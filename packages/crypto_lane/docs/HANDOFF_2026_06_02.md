## Changes this session

### 1. NTP theta sign convention (3 sign bugs fixed)

NTP convention: `θ = (remote − local)`, `θ > 0` → remote clock ahead.

| File | Before (wrong) | After (correct) |
|------|----------------|-----------------|
| `clock_sync.py` | `local_true_time_ns(T, θ) = T − θ` | **Removed** (dead code, zero callers) |
| `pit_join.py:35` | `T_avail = T_node_obs + θ_node + δ_net + δ_proc` | `T_avail = T_node_obs − θ_node + δ_net + δ_proc` |
| `pit_join.py:47` | `T_exch_true = T_exch + θ_exch` | `T_exch_true = T_exch − θ_exch` |

Subtracting θ converts remote→local time. Adding θ (old code) was a leakage risk for `T_exch_true` and an over-conservative delay for `T_avail`.

### 2. BTC mediantime misuse removed

`measure_node_profile_from_btc` computed `θ_node = wall_ms − chain.median_time` (~7,200,000 ms). Bitcoin Core `mediantime` is a ~2h consensus lag, not clock drift. Used as θ_node, it blocked nearly all PIT joins.

Fixes:
- Removed `BtcRpc().getblockchaininfo()` mediantime computation from `measure_node_profile_from_btc`
- Added `MAX_CLOCK_DRIFT_MS = 5000.0` safety clamp on all θ_node paths
- `time` import restored for `time.time_ns()` in live WS probe

### 3. Perp-mid zero-basis bug

When perp kline data was missing, `normalize.py` silently set `perp_mid = spot_mid`, making all basis = 0. Downstream models could not distinguish "real zero basis" from "no perp data".

Fixes:
- `normalize.py`: Added `perp_is_real` tracking, `perp_data_quality_flag` column (1=real, 0=synthetic)
- `feature_matrix.py`: Joins `perp_data_quality_flag` from ticks into output, null-gates 9 basis-derived columns when flag=0
- `spot_perp_ticks.csv` fixture updated with `perp_data_quality_flag=1`

### 4. Live WebSocket RTT probe

New `measure_live_ws_rtt()` async function in `latency_profile.py`:
- Connects to venue WS, sends ping, measures pong RTT
- Venue URL map: `binance_perp`, `binance_spot`, `kraken_spot`, `kraken_futures`
- Falls back to `calibrate_ws_rtt` on `OSError`, `TimeoutError`, `WebSocketException`
- Saves to `venue_profiles.json` with `source: live_measured:<venue>`
- New CLI: `python -m crypto_lane.pipeline measure-live-ws-rtt --venue binance_perp`
- Deprecated `pong` variable renamed (was misleading — `ws.ping()` returns frame bytes, not timestamp)

### 5. `calibrate_ws_rtt` artifact now loadable

`resolve_theta_exch` was filtering out `synthetic_calibrated:*` profiles, but that's exactly what `calibrate_ws_rtt` writes. Fixed: only `backtest_calibrated:*` and `ws_rtt:*` are now excluded. User-intentional `synthetic_calibrated:*` artifacts load on next resolve.

### 6. Kraken env keys

- `env_loader.py`: `HFT3_CRYPTO_KRAKEN_API_KEY` / `HFT3_CRYPTO_KRAKEN_PRIVATE_KEY` aliases + redaction
- `.env.example`: Added both keys

## NTP sign convention — verification proof

Hand-computed example (positive θ):

```
ts = SyncTimestamps(T1=0, T2=60ms, T3=65ms, T4=100ms)
RTT = (100-0) - (65-60) = 95ms   ✓ test_theta_hand_computed
θ   = ((60-0) + (65-100)) / 2 = 12.5ms  (remote ahead)  ✓

PIT with θ_node=10ms (node ahead), θ_exch=3ms (exchange ahead):
T_avail     = 5000 - 10 + 5 + 2 = 4997ms   ✓ test_positive_theta_node_delays_availability
T_exch_true = 5000 - 3 = 4997ms            ✓ (both same → borderline pit-safe)
```

Negative θ (exchange behind local):

```
θ_exch = -100ms  →  T_exch_true = 5000 - (-100) = 5100ms  ✓ test_negative_theta_exch_prevents_false_leakage
θ_exch = +100ms  →  T_exch_true = 5000 - 100 = 4900ms    ✓ test_positive_theta_exch_causes_leakage
```
