# Rithmic R|API+ options-on-futures capabilities: public evidence + conformance path (Rithmic 01)

*Generated 2026-06-12 by WS-0 research workflow (web sources; verify before contract decisions).*

## Findings

- ORDER ENTRY — R|API+ (C++ header RApiPlus.h, ~5,054 lines, mirrored in public GitHub repos) exposes REngine::sendOrder overloads for LimitOrderParams, MarketOrderParams, StopLimitOrderParams, StopMarketOrderParams plus sendBracketOrder, sendOcaList, sendOrderList, linkOrders, exitPosition. Order-type constants: L, M, STP, SLMT, MIT (market-if-touched), LIT (limit-if-touched), E (external) [1]. R Protocol API RequestNewOrder confirms PriceType {LIMIT, MARKET, STOP_LIMIT, STOP_MARKET, MARKET_IF_TOUCHED, LIMIT_IF_TOUCHED}, Duration {DAY, GTC, IOC, FOK}, manual_or_auto flag (MANUAL/AUTO — relevant for CME Tag 1028 audit), and if_touched conditional-release fields [3]. Order entry is symbol+exchange addressed, so options symbols route through the same calls — no options-specific order-entry message exists publicly.
- OPTIONS INSTRUMENT SUPPORT — R Protocol API RequestSearchSymbols.InstrumentType enumerates FUTURE_OPTION=2, FUTURE_STRATEGY=3, SPREAD=9, SYNTHETIC=10 [2]. ResponseReferenceData carries PUT_CALL_INDICATOR, STRIKE_PRICE, UNDERLYING_SYMBOL, EXPIRATION_DATE, presence-bit flags [2]. R|API+ has getOptionList(exchange, productCode, expirationCCYYMM), getInstrumentByUnderlying(underlying, exchange, expiration), getEquityOptionStrategyList, getStrategyList/getStrategyInfo (exchange-listed strategies incl. spread legs via StrategyLegInfo) [1]. Proof of end-to-end options routing on the Rithmic backend: Rithmic's own front-end R|Trader / R|Trader Pro has an Options Board — 'Options on Futures are available through the R Trader platform, and can be viewed and traded through the Options Board' with real-time quotes, market depth and option strikes [5].
- OPTIONS MARKET DATA / CHAIN SUBSCRIPTION — R|API+ subscribeByUnderlying(underlying, exchange, expiration, flags) subscribes an entire option chain; unsubscribeByUnderlying mirrors it [1][14]. Protocol API equivalents exist: request_get_instrument_by_underlying.proto and request_market_data_update_by_underlying.proto (igorrivin mirror) [3]. RequestMarketDataUpdate update-bits include LAST_TRADE, BBO, ORDER_BOOK (aggregated depth), SETTLEMENT, OPEN_INTEREST, HIGH/LOW_PRICE_LIMIT, PROJECTED_SETTLEMENT [2]. No public evidence of options greeks/IV feed from Rithmic — prices/settlements/OI only.
- MBO / DEPTH-BY-ORDER — Official Rithmic announcement (Feb 9, 2018): R|API+ 10.0.0.0 added Depth by Order — 'Programmers now have the ability to determine the position in the order queue of orders for instruments that trade on exchanges that publish order priority information' [4]. R|API+ subscribeDbo(exchange, ticker, bPrice, dPrice) allows per-price-level DBO subscription [1]; Protocol API has depth_by_order.proto, depth_by_order_end_event.proto, request_depth_by_order_snapshot/updates [2][3]. Quantower docs confirm MBO data delivered over Rithmic connections [9]. Whether DBO is enabled for CME options instruments (GLBX publishes MBO for options) is not publicly confirmed — vendor question.
- UDS CREATION — CONFIRMED in R|API+: REngine::createUserDefinedSpread(AccountInfo*, pExchange, pTradeRoute, pEntryType, pStrategyType, iNumLegs, asLegTickers[], aiLegRatios[], pContext, aiCode) with UserDefinedSpreadCreate callback returning the created ticker (UserDefinedSpreadCreateInfo.sTicker) [1][14]. NOT present in the public R Protocol API proto set (rundef/async_rithmic, current as of 2026) — UDS appears to be R|API+/.NET/Java only [2].
- RFQ SUBMISSION — NO public evidence. Zero hits for RFQ/quote-request in RApiPlus.h [1], in the full R|API 13.4.0.0 doxygen docs mirror [14], in RApiPlus.cpp Release.Notes [15], or in any proto file [2][3]. However R|API+ has market-maker-style mass quoting: submitQuoteList(QuoteParams[]), cancelQuoteList(QuoteCancelParams[]), replayQuotes, with Quote/QuoteReport/QuoteReplay callbacks (added per Release.Notes) [1][15] — i.e., two-sided quote submission exists, RFQ initiation does not (publicly).
- MASS CANCEL — CONFIRMED: REngine::cancelAllOrders(AccountInfo*), cancelOrderList(accounts[]), plus cancelQuoteList for quotes [1]; Protocol API request_cancel_all_orders.proto / response_cancel_all_orders.proto present in current proto set [2].
- EXERCISE/ASSIGNMENT NOTIFICATIONS — NO public evidence. No exercise/assign function, class, or callback in RApiPlus.h [1], in 13.4.0.0 doxygen [14], or protos; RithmicOrderNotification.NotifyType enumerates 20 values (ORDER_RCVD_FROM_CLNT … LINK_ORDERS_FAILED) with no EXERCISE/ASSIGNMENT entries [2]. Exercised/assigned futures positions presumably appear via position/PnL replay (replayPnl, instrument_pnl_position_update) — unverified, vendor question.
- PLATFORM EVIDENCE — Rithmic-backed third-party platforms (EdgeClear list): EdgeProX, Sierra Chart, Investor/RT, MotiveWave, Bookmap, Jigsaw Trading, ATAS, MultiCharts, Quantower, Agena Trader, Trade Navigator, QST [8]. Options-on-futures trading via Rithmic is confirmed for R|Trader/R|Trader Pro (Options Board) [5] and claimed by Quantower: 'Rithmic technology provides access for trading futures and options on CME, CBOT, NYMEX and other exchanges' [9]. Most order-flow platforms (Bookmap, Jigsaw, ATAS) are futures-only in practice; QST is the options-analytics-heavy one on the list [8].
- CONFORMANCE PROCESS (assembled from public sources): (1) request API access via rithmic.com/api-request form or rapi@rithmic.com (named contact for rapiplus.dll/SDK distribution) [13]; broker/FCM (Optimus, AMP, EdgeClear) co-sponsors and 'can work together until pass the conformance test' [17]; (2) Rithmic provisions dev credentials for 'Rithmic Test' and 'Rithmic Paper Trading' systems [12]; (3) develop against test env — conformance must be passed even to use the API on Rithmic Paper Trading [11]; (4) conformance exercises ~8 areas: connection mgmt/heartbeats/reconnect, market-data subscription handling, full order lifecycle incl. modifies/cancels/rejects, error handling, risk-limit adherence, recovery/resync, message-rate throttling, logging/timestamps [10]; (5) after passing, Rithmic issues a unique 4-character app prefix (app name must carry it), the SSL cert-auth params file, and the live URIs/gateway points [11]; (6) switch system name from 'Rithmic Paper Trading' to 'Rithmic 01' (live) and select gateway (Chicago-area for CHI404 colo) [11]. Timeline: 'days for simple integrations, weeks or longer for complex trading systems' [10]; Rithmic direct-inquiry response times reported slow — route through the FCM [17].
- COSTS (broker-published) — AMP: R|API connection fee $100/month per User ID + $25/month Rithmic User ID = $125/month flat, + $0.10/contract live trade-routing fee, µs-granularity platform timestamps [6]. EdgeClear advertises '$20/month and $0.10/contract' for Rithmic access (API or R|Trader Pro) [8] — fee structure is clearly FCM-negotiable. Options routing presumably same $0.10/contract (no separate options price published) [5].
- HFT TIER — R|Diamond API = R|API+ plus direct connection to Rithmic's market-data handlers and exchange-facing gateways, bypassing the ticker plant; orders pre-staged at the gateway post-risk-check and released by 'a small message ... indicating the order number to be released and the price'; stated transit time (md read → order release) < 250 µs [7]. Pricing/eligibility/colo terms not public.
- VERSION STATE — current R|API+ observed in the wild: 13.5.0.0 (developer log evidence, 2025-era project) [16]; full doxygen doc mirror exists for 13.4.0.0 (.NET/Java com.omnesys.rapi namespace) [14]; protocol API protos use proto3 with PB_OFFSET=100000 MNM field ids [2]. R|API+ also exposes subscribeAutoLiquidate/unsubscribeAutoLiquidate (auto-liquidation events), replayExecutions, replayHistoricalOrders, modifyOrderRefData [1][14] — useful for reconciliation design.

## Open questions

- Does CME permit MARKET/MIT/LIT order types on options instruments through Rithmic, or are options limited to limit/market-with-protection at the iLink layer (Rithmic may reject locally)?
- Is Depth-by-Order (MBO) enabled for CME options on futures via Rithmic, and at what cost — GLBX.MDP3 publishes options MBO, but Rithmic's options DBO coverage is publicly unconfirmed.
- Is there ANY RFQ submission path (the single biggest publicly-unconfirmable gap — critical for 0-45DTE spread liquidity where RFQ is standard workflow)?
- How do exercise/assignment and expiry events reach an R|API+ session — callback, position replay on next login, or FCM back-office report only?
- Does the public RApiPlus.h version found (with UDS/quote functions) match current 13.5.x, and is UDS available on Protocol API or only the compiled R|API+ libs (Linux/Windows C++)?
- Is submitQuoteList available to a regular DMA customer account or only to registered market-maker programs?
- Actual conformance wall-clock for an experienced team in 2026 (public anecdotes say days-to-weeks but no 2025-2026 datapoint), and whether Rithmic charges any conformance/cert fee.
- R|Diamond API: eligibility threshold, monthly cost, and whether the <250µs claim holds from CHI404 cross-connect; separate conformance required?
